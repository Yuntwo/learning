个人助理的“记忆”怎么进大模型？

[小红书正文]
很多人会把“用户记忆”“用户画像”“system prompt”直接画等号。

但从工程实现看，这三个东西其实不是一回事。

如果你问一个成熟的个人助理产品：它为什么看起来像“记得你”？真正的答案通常不是“把你的所有信息都写进系统提示词里”，而是系统在每次调用模型前，都会重新组织一遍与你当前问题相关的上下文。

我把这件事拆成 5 个重点。

1. 少量稳定偏好，确实可能常驻在高优先级提示层

比如：默认中文、偏好简洁回答、用户是工程师、危险操作先确认。

这类信息变化不大，而且对很多问题都通用，所以常常会放在 system prompt 或 developer prompt 一类的高优先级位置。

但注意，这通常只是一小部分“稳定背景”，不是全部用户记忆。

2. 更主流的做法，是把长期记忆存起来，按需检索再注入

成熟系统更像这样工作：

先把用户的长期信息存到 memory store。
当新问题进来后，先判断这次和哪些记忆相关。
再只取少量高相关记忆，拼进本轮上下文。

这和知识库检索很像，只不过检索对象不是产品文档，而是“关于这个用户的长期事实”。

所以重点不是“是不是 system prompt”，而是“有没有在这轮推理前被取回来并影响答案”。

3. 有些画像根本不会直接给模型，而是只在业务层起作用

这一点很容易被忽略。

比如系统知道你是专家用户，可能就直接选一种更短、更少铺垫的回答策略；如果知道你是新手，可能就默认多给步骤。

再比如，用户偏好短回答、喜欢表格、常用某类工具，这些信息有时只会影响：

- 用哪个模型
- 走不走工具调用
- 回答长度怎么控制
- 要不要先问澄清问题
- 优先查哪些知识源

也就是说，画像被系统用了，但未必是以自然语言原样喂给模型。

4. 成熟实现通常会把记忆分层，而不是一股脑塞进去

一个比较常见的分层方法是：

- 稳定偏好：语言、风格、专业背景
- 长期记忆：长期项目、目标、长期约束
- 短期工作记忆：当前会话里的任务状态、待办、暂存结论
- 策略规则：哪些操作要确认、哪些事情默认不做

这几层东西不一样，所以处理方式也不一样。

如果把它们全部混成一段“用户画像”塞进提示词，效果通常不会太好。

5. 真正的难点不是“塞哪里”，而是“取什么”

业界里做 memory system，最难的往往不是多写一段提示词，而是：

- 什么值得记
- 什么时候取
- 取多少条
- 如何避免过期信息误导回答
- 如何避免画像绑架这次真实任务

比如用户长期偏好“简洁”，但这次问的是复杂架构问题，那系统就不应该机械地继续极简回答。

所以更好的做法是把画像当成默认偏好，而不是绝对规则。

你可以把这件事理解成一个对照区块：

信息类型              常见处理方式
稳定偏好              常驻高优先级提示层
长期记忆              按相关性检索后注入
短期任务状态          放在当前会话或工作记忆里
策略信号              只在业务层影响路由与参数

如果只记住一句话，我会这样总结：

个人助理确实会把“用户记忆”用于和大模型交互，但成熟实现更像是“分层存储、按需检索、选择性注入”，而不是把所有用户画像永久写死在 system prompt 里。

所以一个助理看起来是不是“懂你”，核心通常不只是模型本身，而是它前面的 memory system、检索策略和上下文编排能力。
